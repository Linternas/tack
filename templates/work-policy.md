## Unified task and session records

- Use the globally installed `tack` CLI as the current-state source for tasks, decisions, dependencies, verification and resumption. At substantive work start inspect `tack status` / `tack resume ID` and reuse matching work; brief questions need no task.
- Use `handoff-state` for checkpoints. Tack records work; it never starts or coordinates agents. Optional orchestration is installed and invoked explicitly per project. Bind manually started development sessions with `tack bind THREAD_ID TASK_ID`; never guess ownership from the most recent task. Installed hooks require trust and actual event receipt before automatic recording is confirmed.
- Preserve latest-version checks and reconcile conflicts. Record task completion separately from session/execution termination; completion requires actual scoped verification. Keep failed and unexecuted checks factual.
- Keep work plans, progress, QA results and handoffs in Tack, not parallel Markdown ledgers or `~/.codex/work-state`. Preserve durable product/API/design source documents and historical records. Only an explicit standalone deliverable request authorizes another report/file.
- CLI records work without a server; Dashboard is optional. Preserve the existing `~/.local/share/agent-work` DB and project identities. On permission/write failure report unsaved state and resolve within approved permissions; never silently create another DB, claim success, or use a server to bypass sandbox restrictions. Configuration changes do not prove an active session can write.
- Respect existing authorization: a goal does not authorize remote Git writes, deployment, destructive actions, messages, or broader sandbox access. Keep secrets and full conversations out of records.
